\section{Rubric Details}
\label{app:rubric}

The judge returns one JSON object per pair. The schema constrains the fields jointly: a score of 2 requires \code{answer\_validity = correct}; a score of 1 requires \code{correct} or \code{minor\_error}; a score of 0 requires \code{major\_error}, \code{uncertain} or \code{not\_applicable}; an unevaluable query has no score, validity \code{not\_applicable} and a code from the last group below. Table~\ref{tab:codes} lists the reason codes allowed with each score. The prompt is \code{prompts/judge\_prompt.md} (SHA-256 \code{031ac72b649ae979\ldots}); \code{guideline\_version} is always \code{strict-math-retrieval-v1}, so the hash, not the version string, identifies the prompt text.

\paragraph{Declined pages.} The query extractor declines 14.9\% of documents: reference pages only (39.5\% of declines), corrupted text (24.8\%), a missing figure or context (19.6\%), not mathematics (8.5\%) and no problem stated (7.7\%).

\paragraph{Near-duplicate review.} MinHash uses 128 permutations over word 5-grams after stripping \verb|\displaystyle| and NFKC normalisation, with two LSH banding schemes (16 bands $\times$ 8 rows and 32 bands $\times$ 4 rows). The 762,610 proposed deletions split into 583,077 whose document has no content that the kept copy lacks, which are deleted, and 179,533 that go to GPT-5.6-Sol; the reviewer was calibrated on 96 hand-checked items and got all 96 right, and a failed call counts as ``keep''. Of the 177,431 proposals it reviewed, it kept 54.8\%: 49.9\% had substantive content the other copy lacks and 4.9\% were different documents. Pairs close to the 0.80 threshold can escape, because LSH candidate generation is probabilistic; normalising more aggressively before hashing merged 0.026\% more groups on a 120,000-document sample, all of them true duplicates.

\paragraph{Scoring.} Pairs are packed into rows of up to 65,536 tokens with position ids restarting at each pair, and scored with FlashAttention-2~\citep{dao2024flashattention2} variable-length attention in bf16. Before producing any output, each worker scores 256 held-out pairs and compares them with the training-time predictions; it must reach a Pearson correlation of 0.999, and the measured value was 1.00000.

The release is a Hugging Face dataset with four configurations. \code{corpus} holds \code{did}, \code{text} and \code{n\_chars}. \code{queries} holds \code{qid}, \code{text}, the \code{source\_did} the query was extracted from and \code{from\_page\_question}. \code{judgments} holds one row per judged training pair with its rank in each retrieval route, its fusion score and stage, the label, the judge, the 8B raw score, the dense and reranker scores, and the LLM judge's validity, reason codes, confidence and rationale. \code{qrels} lists the relevant documents of each test query. Document ids are \code{"d\_"} plus the first 24 hex digits of the SHA-256 of the lowercased normalised text; training query ids hash the raw upstream page, and test query ids hash the normalised query text.

\section{Queries in Numbers}
\label{app:queries}

Of the 1,853,389 training queries, 797,856 (43.0\%) are a page's own question, minimally edited, and the rest were composed by the extractor. 64,544 training queries have no \code{source\_did}: near-duplicate removal took their source page out, and its surviving copy is not a full answer or none was found, but another document is a full answer. On 2,901,088 judged source pages, the LLM judge gave 70.04\% a 2 and 11.70\% a 0.
