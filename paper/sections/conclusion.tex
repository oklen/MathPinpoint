\section{Conclusion}
\label{sec:conclusion}

MathPinpoint frames math retrieval as finding the page that solves a given problem correctly, and provides the data to train and test retrievers for it: a corpus of 3.5M mathematical web pages, 1.85M training queries with 43.5M judged candidates whose judge is recorded on every row, and 6,173 test queries labeled by two LLM judges and an arbiter. Fine-tuning a strong embedding model on the training split improves it on the test split, by more than the standard metric shows, and brings it level with BM25, which is a strong baseline for a task in which the same problem recurs almost verbatim across the web. The same analysis carries a general lesson for benchmarks built from pooled LLM judgments: the share of a system's ranking that the labels cover should be reported with every score, because at this scale it decides which system looks better. We release the data, the exact prompts that produced it and the evaluation code, so that the labels can be audited, extended to new systems' rankings, and replaced by better judges.
